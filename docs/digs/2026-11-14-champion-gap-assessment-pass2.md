## Q1 · 最终目标的可行性与能力上限

先把「冠军水平对战模拟 + 卡组 + 策略评估」拆成三个可独立判定的子目标：

| 子目标 | 判定 | 论据 |
|---|---|---|
| **冠军水平的对战模拟**（引擎能正确模拟冠军卡组对局） | ✅ **已达**（90%） | 池内 9 卡组 134 DSL 零缺口、18,000 局零失败；缺口只剩池外覆盖（YAGNI 纪律内） |
| **冠军水平的卡组评估** | ✅ **可达**（路线图 A2，数周） | 原料齐（CN 卡组级 383 场 + intl 对局级 7 卡组 + sim 定量敏感性）；形态参照 metamages；瓶颈是产品层不是能力层 |
| **冠军水平的策略评估** | ⚠️ **半可达，上限要分两段说** | 见下 |

**策略评估的上限分段**：
- **可达上限（承诺级）**：「显著超越启发式的学习类策略 + 可审计的策略分析」——Kaggle 公开解法已证明此路径可复制（见 Q3）；我们的 M12 管线（教师采集→蒸馏→numpy 推理）是现成地基。合理预期：**上位赛事水平的陪练/评估**。
- **研究上限（投注级，不承诺）**：字面意义的「世界冠军级 PTCG AI」——Kaggle 官方赛表明这是开放竞赛题（TPC 出资悬赏），单人单机数月投入是**研究赌注**不是工程计划。
- **永不可达（本质）**：「sim 内冠军 = 真实冠军」——效度天花板（格级零相关已钉死）使 sim 策略评估永远限「同模拟器内」。但注意：**陪练/评估用途对效度天花板的敏感度远低于预测用途**（相对比较与训练信号的退化是渐进的，不是归零）——这是策略评估值得做的核心理由。

**Q1 结论**：三子目标中两个可达、一个「可达其可达上限、但字面冠军级是研究赌注」。建议把正式目标表述为：**「冠军级卡组评估 + 上位赛事级策略评估」**，不承诺字面冠军级 AI。

## Q2 · 实现方案：还可以引入什么

按层列出可引入项（★=外部已验证有效，我们完全没有）：

**策略层**
1. ★ **BC + RL + MCTS 混合栈**（Kaggle 上位公开解：Dragapult 行为克隆 → RL 微调 → 带价值网的 MCTS 运行时；[公开实现](https://github.com/henriquetakahiroito/pokemon-tcg-ai-battle)：从 6,533 局真实对局 JSON 挖掘数据训练 numpy 价值网 + 确定性信息集 MCTS，TrueSkill 600→948/1 小时）
2. ★ **价值网进搜索**（我们的 M11 评估器目前只做 rollout 截断——从未接入搜索引导；Kaggle 路径证明价值网驱动 IS-MCTS 是性价比最高的单点提升）
3. **自生成对局挖掘**（我们的快照采集器已在产决策点数据；sim 自对弈是**无限量、无隐私、无分布偏移**的动作级数据源——intl 真实数据只有胜负没有动作，自生成是唯一动作级来源）
4. ★ **Elo/联赛评估基础设施**（[kego](https://pypi.org/project/kego/) 式：agent 种群 + Elo 联赛 + 模型注册；我们把 agent 对比停在胜率 CI，没有种群级评估面）
5. 集成确定性化 + 自适应预算分配（[2026 arXiv](https://arxiv.org/html/2607.13007v1)：多世界投票 + 动态资源，收益 2–3pp 级）

**分析层**
6. ★ **metamages 式选卡器**（meta share × matchup 矩阵 → 期望胜率最大化 + 蒙特卡洛 field 模拟）——Pass 1 路线图 A2
7. **败局解剖产品化**（终局类型 × 死亡回合分桶 + 系统回放抽样）——Pass 1 路线图 A1
8. ★ **对手建模 / 剥削层**（扑克 AI 范式：GTO 锚 + 剥削调整；[AlphaExploitem](https://arxiv.org/html/2605.09150) 证明可超越纳什均衡剥削弱对手而不失均衡稳健；对我们 = 「强基准策略 + 针对已知 meta/对手倾向的偏离层」——冠军级备赛的核心动作恰恰是针对预期 field 的 meta-gaming）

**数据/效度层**
9. 国际窗 matchup 表产品化（7 卡组真实格级数据已在库里，缺呈现与选卡器接线）
10. LLM 分析助手层（策略解释/演练题生成/复盘问答——注意：Owner 此前两次关闭 LLM 线，若重开仅限**分析辅助**角色，不进对局控制路径、不做胜率宣称）

**引擎层**
11. 残局求解器（小状态空间回溯求解，附带在搜索里做残局验证）
12. **原生高性能核心**（见 Q4——RL 的前置约束）

## Q3 · 技术盲点（我们之前完全没考虑过的路径）

按「盲点程度 × 潜在收益」排序：

| # | 盲点 | 为什么之前漏了 | 外部证据 |
|---|---|---|---|
| B1 | **BC+RL+MCTS 混合栈** | M12 终判后我们把「学习线」整体收口，从未重新审视「混合栈」——蒸馏只是其中最弱的一环 | Kaggle 上位解全是混合栈（BC/RL/MCTS 至少三取二） |
| B2 | **价值网进搜索引导** | M11 立项时目标定为「rollout 截断降成本」，搜索引导这个更大用途从未立项 | 同上；价值网是 Kaggle 解的核心部件 |
| B3 | **自对弈 episode 挖掘** | 采集器为蒸馏教师而建，数据源视角停在「MCTS 教师」，没看见「自己的对局流就是无限训练数据」 | Kaggle 解从 6,533 局 JSON 挖矿；我们有无限产能 |
| B4 | **对手建模/剥削层** | 整个 validity 线都在做「平均表现」，从未考虑「针对特定对手/meta 的偏离」——而真实冠军备赛的主要动作就是 meta-gaming | 扑克 AI 二十年主线（GTO 锚 + exploit）；[AlphaExploitem](https://arxiv.org/html/2605.09150) |
| B5 | **Elo 联赛评估面** | 评测口径停在「成对胜率 CI」，没有 agent 种群/迭代进化的评估基础设施 | kego/TrueSkill 生态 |
| B6 | **引擎吞吐 = RL 前置约束** | task 037–042 后把性能当「已优化」封存；但那是 MCTS 口径的优化，RL 需要 10³–10⁴× 吞吐 | agents-lab：Python 绑定 C++ 的每调用开销是 self-play 瓶颈；deckgym-core 用 Rust 解决 |

**不构成盲点、已正确关闭的**：ISMCTS 替换确定性化（文献结论混合：[Dou Di Zhu 研究](http://orangehelicopter.com/academic/papers/cig11.pdf)显示 IS-UCT 无稳定平均收益；我们的 freeze-set 部分确定性化已是合理工程点，集成化即可）、CFR 系（两人零和深栈扑克场景的收益结构与我们不同，优先级低）。

## Q4 · 与现有架构的兼容性（Owner 已声明可接受重构）

**架构事实**：引擎 = 纯 Python + DSL 解释器（规则零硬编码）；Agent 统一 `observe(可见状态, 合法行动) -> 行动`；runner/结果库/报告层成熟；runtime 纪律 = numpy only（torch dev-only 已批）；1726 测试 + events_hash 逐局等价是**黄金参照**。

**无需重构即可引入**（全部挂在现有接口上）：分析层全部（6/7/9）、Elo 联赛（新模块）、对手建模（Agent 内）、价值网进 MCTS（M11 资产 numpy 化已是现成模式）、episode 挖掘（采集器扩展）、集成确定性化（搜索层参数）。

**需要大改但不颠覆范式**：
- **方案 R1（推荐）：原生核心 + Python 外壳**。Rust/Go 实现规则骨架（状态机/伤害/昏厥/奖赏——不含卡面逻辑），DSL 解释器**预编译**为原生效果链；Python 侧保留 Agent/DSL 定义/报告。验收 = 现有 1726 测试全绿 + **events_hash 跨实现逐局等价**（黄金参照的巨大价值：重构正确性可机器验证）。风险：DSL 语义全保真工作量大（134 份定义 × 原语全集）。
- **方案 R2（渐进）：Python 引擎 + 批量并行环境**。不重构引擎，用多进程 env pool（已有 16 workers 基础设施）+ 蒸馏小网 rollout 把有效吞吐顶到 RL 可用下限。成本最低但天花板明显（单局 ~0.02s → 16 workers ≈ 1.5k 局/s 量级）。
- **方案 R3（中间）：Cython/Numba 热点 + 解释器预编译**。不动架构，把解释器热点与状态拷贝向量化。性价比介于两者之间。

**重构红线（什么绝不能动）**：信息纪律（Agent 只可见过滤视图）、单一可注入 RNG（种子确定性 = events_hash 等价的前提）、DSL 数据驱动（引擎不认卡面）、结果库独立、claims register 宣称纪律。R1 若做，这些红线本身就是重构的验收标准。

**兼容结论**：Q2/Q3 的方案中 **~70% 挂在现有架构上零重构**；真正需要重构的只有「RL 强策略」这一条线的吞吐前提（R1/R2/R3 三档可选，R2 可立即起步、R1 作为 B 线立项时的赌注）。
