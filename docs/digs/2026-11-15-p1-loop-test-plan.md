## 1. 每任务验证证据矩阵

### task 135（池文件修订，零代码）

证据形态 = 可复现脚本输出 + 文档 diff 清单，不写新测试（配置层）。

- **选取可复现**：侦察脚本（复用 t068 scout 口径）钉 SQL + 钉窗口，输出 6 套 + 第 10 套的候选 deck_id 与名次证据；重跑逐字节一致。
- **合法性**：每套新表 `bfsim check-deck`（或 dsl-check --db 口径）过 standard-2026-09-16；失败表不得入池（回 task 068 替补纪律）。
- **wur 重算**：近窗 wur 值由脚本算出，不许手填；头部注释覆盖率重算值可复现。
- **回归点**：`test_coverage_gate.py:244`（v2 池 strict 口径全覆盖）动态读池文件——**红窗口 = 「135 池文件落盘而 136 未合」**（136 合入时池文件仍是旧 v2，本就绿，不是检查点）。落库顺序纪律（136 先、135 池文件后）消除红窗口；若 135 必须先落盘，135 验收 6 的 manifest 逃生分支生效，本测试同步改为「显式预期阻断清单」并在 136 收官时恢复——该过渡态在 loop 出口 checklist 3 收口，不允许带进 gate；
- 068 原始锁定段以注释保留，diff 可证一字未动。
- **拍板项留痕**：赛富豪土龙节节 en_archetype 的 intl 映射结果（或校准缺口标注）写入 task 文档。

### task 136（DSL 批，三闸）

- 闸 1：`dsl-check --db` rc=0（主会话亲验，不信子代理转述）；能量回收前置分支——text_raw 等价类比对结论（同文本补挂 vs 异文本新档）逐卡记录。
- 闸 2：单卡测试绿 + 主会话独立复验；若触发引擎扩展，扩展部分按 138 同款「只加不改」证据（既有测试零改动）。
- 闸 3：核销清单交付 Owner（交付物判据，清单格式同 task 132）。
- **解除阻断实证**：用一张含 I 标卡的表跑 `bfsim run` dry-run strict，阻断从「拒」变「过」。
- 份数：收官实测 `cards/` 计数，与「当时实测基线 +N」断言一致（N = 136 异文本新档数；若 138 先于 136 合入，基线相应 +1——断言以收官时实测为准，不硬编码顺序）。

### task 137（矩阵重跑 + 快照，零代码）

- **零失败**：22,500 局平 0；失败局>0 即停查，不补跑掩盖。
- **可复算抽查**：抽 1 个无向格（建议多龙黑夜 vs 赛富豪土龙节节，新表新对）用同实验定义 + 同种子区间整格重跑，逐局结果一致。
- **快照回喂一致性**（task 125 纪律）：matchup-snap 回喂 field-pick 的装配 diff 为空；逐格一致显式断言。
- **field-pick 冒烟**：10 套排序输出 + 来源构成列 + ⚠标注 + 限定语三行头注齐全；抽 1 卡组期望胜率手算复现（钉种子 MC）。
- **C1 口径**：intl 旧窗错位告警在场 = 预期（task 107 既成事实），非事故；若告警缺席反而要查（可能说明窗口元数据没更新）。
- **成本门**：墙钟 ≤ 预算 ×2 熔断。

### task 138（引擎扩展 + DSL）

- TDD：每扩展红→绿 commit 序证据；落地后既有测试零改动（全量绿且测试文件 diff 为空）。

### task 130（换卡搜索器，纯报告/实验层）

- 设计文档四问：每问「定案或 trade-off 表 + 待拍板项」显式结构。
- 原型单测：候选生成器过滤链（DSL 覆盖→赛制→60 张结构合法）、两阶段调度（筛选→确认 CRN 成对）、排序输出——各带单测。
- **E2E 交叉验证**（核心判据）：搜索器在太晶伊布表（mik_moe:711874）上 vs t1114 三对手，是否自己找到 t1114 人工刀位同类结论（火伊布 ex 出手保障 / 保护方向）；净胜 CI 与 t1114 量级互证。
- 限定语：原型输出头注断言（自对局先验）。
- 零行为变更：不动 Agent/DSL/引擎——diff 范围审查为报告/CLI/实验层。

## 2. Loop 出口 checklist（全部勾完才移交 M14 gate）

1. 五任务 task 文档「结果与遗留」填实，证据链接齐；
2. 全量 1785+N 绿 + ruff 零告警（N = 136/138/130 新增测实数）；
3. **联合 strict 演习**：v2.x 池 × 矩阵实验定义 `--strict-coverage` 全过（135+136+138 合并后的第一道集成关）；**137↔138 岔口收口**：若 137 开发期曾按 137 验收 2(b) 非 strict 跑批（138 未完成），gate 前须以 strict 口径重跑矩阵，或显式记录 Owner 接受有损口径——不允许非 strict 矩阵静默进 gate；
4. 快照三件齐：`matchup-snap`（v2.x 窗）、`field-snap`（2026-11 窗）、field-pick 冒烟输出，互相窗口错位 ≤28 天（除 intl 格按 §1.137 C1 口径）；
5. M14 gate 输入包：选卡器命令行 + 快照路径 + 读数口径（C1 告警/限定语）一页纸，Owner 可独立执行；
6. 闸 3 核销清单状态明示（132 积压 + 136 新批 + 138 新批——gate 前 Owner 批量核销或显式延期）；
7. CHANGELOG Unreleased 段记账齐（136/138/130 产物）。
