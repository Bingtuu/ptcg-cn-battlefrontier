# 导入三种入口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让研究者用复制即可跑的实验模板进入卡组（`deck_id`、池 YAML、本地「卡名×张数」），并用只读查询从 ptcg-cn.db 拉出池内 archetype 的真实逐桌对阵对照，双轨落盘。

**Architecture:** 不新造卡组装载器。`source: db` 与 `source: file`（`parse_decklist` 的「N 卡名」）和 `matrix.pool` 已经存在。073 补三份模板，以及 `battlefrontier/data/pairings.py`：以 SQLite `mode=ro` 读 `v_pairing_players` ⋈ `v_tournament_weights`，只保留调用方给出的 archetype 与日期窗。`bfsim pairings` 把聚合格写成 Markdown/HTML 与 CSV/JSON。不做构筑 GUI，不改 074/075。

**Tech Stack:** Python 3.12+、Pydantic 实验定义、sqlite3 只读 URI、pytest、ruff。

**权威设计：** `docs/superpowers/specs/2026-10-28-post-071-roadmap-design.md` §3 的 073。

## Global Constraints

- 受众是研究者/备赛：CLI + 文件 + 导出。不做产品 GUI、卡组构筑器。
- 主库只读。不伪造校准 |Δ|，也不把抽样行当成全量分母。
- 导出默认双轨：Markdown（HTML 由它转义）与 CSV/JSON，聚合数字同源。
- 不做 074 的过程日志，不做 075 的换卡报告，不做 JEV/LLM。
- 种子确定性与既有实验定义不变。pytest 与 ruff 对改动路径通过。

### Task 2: 只读对阵对照与双轨包

**Files:**
- Create: `battlefrontier/data/pairings.py`
- Create: `battlefrontier/report/pairing_pack.py`
- Modify: `battlefrontier/cli.py`（子命令 `pairings`）
- Test: `tests/test_pairings.py`

**Interfaces:**
- Produces: `pairing_contrast(db_path, archetypes, *, date_from, date_to, basis, division="master", sample_limit=20) -> PairingContrast`
- Produces: `write_pairing_pack(directory, rep) -> dict[str, Path]`

- [x] **Step 1: Write the failing test**

用临时 SQLite 建表 `v_pairing_players` 与 `v_tournament_weights`。窗内 Alpha×Beta 两局决定局（一胜一负）、一局 winner_side=0、一局镜像、窗外日期、非 master、非 intl_aligned、池外 Gamma 各一行。断言有向格 n=2、wins=1；抽样含 winner_side=0 且不含镜像；`mode=ro` 下 INSERT 失败。

- [x] **Step 2: Run test to verify it fails**

Run: `python3 -m pytest tests/test_pairings.py -q`
Expected: FAIL（模块不存在）

- [x] **Step 3: Implement the query and the pack**

连接 `file:{path}?mode=ro`。SQL 只 JOIN 上述两个视图，`date BETWEEN`，`basis` 相等，`division` 相等或 NULL，双方 archetype 都在给定集合且不相同。`winner_side` 为 1 或 2 才进入有向格（与 `matchup.sql` 相同：0 不进分母）。抽样按 `tournament_id, phase, round, table_no` 取前 `sample_limit` 行，`sample_total` 是过滤后的行数。Markdown 内嵌 `format_pairing_contrast`；HTML 用 `deviation_html`；CSV/JSON 的 `n`/`wins`/`winrate` 等于 `PairingCell`。

CLI：

```bash
bfsim pairings --pool config/target-pool.v2.yml --out results/v2-pairings
```

缺省窗口与 basis 用 `REAL_DATE_FROM` / `REAL_DATE_TO` / `REAL_BASIS`，与 `bfsim calibration` 对齐。没有库时命令会失败，测试用临时库，不填正式数字。

Run: `python3 -m pytest tests/test_pairings.py tests/test_ingress_templates.py -q`
Expected: PASS
