- PRD §7.3 已为 MCTS 预留架构（状态快照 / determinization / evaluate 纯函数）

## 3. 四条工作线范围

### 3.1 Agent 升级线（主线）

**目标**：消减偏差表中由 Agent 决策质量贡献的部分。

- **task 031 偏差归因**（纯分析，零风险）：
  - 对象：|Δ|≥25% 的全部格（M6 基线含赛富豪 4 格 + 其余待筛），每格给出三因素判定与证据
  - 方法：①`bfsim report <id> --decisions` 决策聚合（关键决策点选择分布 × 胜率）；②事件流回放抽查（render 人类可读回合记录，对照 db 侧真实卡组的典型打法）；③对照实验——同格换卡组变体（variants 设施既有）分离「卡表差」与「Agent 差」；④DSL 单卡测试复核嫌疑卡
  - 产出：归因报告（逐格结论 + 修复清单分类：Agent 规则项 / DSL 缺陷 / 卡表差不可修项），落 `docs/` 并归档 task
- **MCTS**（M8，门控于 D2-3）：技术口径预登记——determinization 采样走同一可注入随机源（不破坏种子确定性硬验收）；rollout policy 复用 heuristic evaluate 纯函数；先单格验证（赛富豪 vs 苍响）再铺开
- **RL**：二期不做。观察项，前提 = MCTS 落地后仍有结构性差距且样本成本可承受

### 3.2 LLM harness 铺开线

**目标**：把一期试验结论（first_pass 34/42、人工修改 0 行）转正式产能，按 D2-4 增量模式运行。

- 触发场景：卡池 v2 缺口批次、夜光能量异文本类等遗留补写、新机制配套卡
- harness 不变更：skill + 严格 prompt + 三道闸 + authoring-log；质量口径延续（first_pass / human_edit_lines 逐批记录）
- 不做：全库铺开（无消费方，YAGNI；gate3 人工核销是真实瓶颈）、程序化无人值守批跑（触发器未到）

### 3.3 引擎收尾线

**目标**：清掉一期已知的四个尾巴（D2-5 清单），全部为独立小 task，不阻塞主线。

- damage 空战斗场 no-op 化需先出规则出处核对（rules-manual / Q&A），改动落 DSL 原语语义，影响面 = 既有失败局形态从 error 变正常结算——需重跑影响格确认胜率口径不变
- 附录 A 三候选走既有核销流程（逐条裁决 + 用户确认）

### 3.4 环境演进线

**目标**：为 Mega 环境（J 标）到来做准备，但只在数据与池需要时动手。

- 步骤：①Mega 机制规则调研（简中官网规则页 + 规则决议流程，输出调研笔记进 rules-reference）；②db 侧数据需求清单（赛事覆盖 / 新字段）；③卡池 v2 锁定（WUR 驱动，复用 task 024 替补补位机制）；④缺口批次走 3.2 增量 harness
- 前提依赖：db 侧 Mega 环境赛事数据积累（同一期 M6 前置模式）

## 5. 非目标（二期明确不做）

- RL Agent（远期观察项）
- DSL 全库铺开 / 程序化无人值守 LLM 批跑（触发器未到，见 D2-4）
- 分布式执行（一期口径维持：单机多进程足够）
- 裁判判罚 / 超时等赛事规则；V-UNION 不实现（一期口径维持）
- Mega 机制实现承诺（调研先行，实现与否由池 v2 驱动）

## 6. 验收策略

- 一期硬验收全部延续（全量 pytest 绿 + ruff 零告警 + 确定性 + 主库只读），每个 task 收口必过
- M7 纯分析验收 = 报告可复算（数字全部可经 `bfsim report` / `bfsim calibration` / 事件流查询重放）
- M10 复校准：偏差表同口径重跑（真实侧口径常量沿用 calibration.py 钉死值），meta 回显对比基线版本
- LLM 增量批次继续三道闸 + 质量数据逐批落 authoring-log

## 7. 开放问题（二期实现期回答）

- 归因三因素的定量分离口径（对照实验设计：换卡表不换 Agent / 换 Agent 参数不换卡表的格子选择）——task 031 任务书定稿
- MCTS determinization 的采样预算与并行口径（若 M8 立项）
- 卡池 v2 规模（维持 9 套还是扩）与密勒顿回池的合并决策
- Mega 机制对引擎骨架的冲击面（规则盒 / 奖赏数 / 新阶段时点）——调研后回答
