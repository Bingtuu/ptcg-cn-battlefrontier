## 1. 目标与动机

HeuristicAgent 是全部管线的公共底座：matrix 校准基线的两侧 Agent、MCTS 的 rollout 策略。M8c 预算标定证明「加搜索预算不经济」（400u 才 54.2%），瓶颈在 rollout 质量；M8a 证明启发式修复能实质改变胜率。因此对启发式参数做系统性搜索，是投入产出比最高的决策层升级路径，也是未来学习类 Agent（方向 A）的最小可行第一步与对照基线。

**产出**：①一套确定性、可复算的参数搜索设施（tune 子包 + CLI）；②一组经 holdout 验证的最优 HeuristicParams；③维度敏感性报告（哪些参数真正影响胜率——测试智能化的量化素材）；④最优参数的全 matrix 复校准对比（vs M6 基线）。

**非目标（YAGNI）**：不调 MCTS 超参（worlds/iterations 已定案 D-035-5）；不做卡组构筑搜索；不引入任何学习框架/重型依赖；默认参数不静默变更（回写需用户裁决）。

## 2. 搜索空间（D-T1）

HeuristicParams 共 17 字段（`agent/heuristic.py:44-69`），分三类处理：

| 类别 | 字段 | 处理 |
|---|---|---|
| 连续权重 8 维 | w_hp / w_damage / w_retreat / w_prize_diff / w_board / w_hand / w_energy_ready / w_deck | **进搜索**，乘法网格（尺度无关，对正负号权重一致适用）：每维网格 = {0, ×0.25, ×0.5, ×2, ×4}（0 = 关闭该因子） |
| 整数 2 维 | max_bench_setup（1..5，步 1）/ deck_low_threshold（0,3,6,9,12） | **进搜索**，枚举网格 |
| 布尔开关 7 个 | use_abilities / play_items / play_supporters / play_stadiums / attach_tools / retreat_when_powerless / deck_protect | **不进搜索，固定全开**——M8a 后这些开关的「开」均为已验证的修复行为，关掉是退化方向；128 组合枚举成本/收益不成比例。若坐标下降后某权重趋 0 再个案评估 |

## 3. 评估协议（D-T2）

- **fitness 定义**：候选参数 vs 当前默认参数，在训练配对集上的平均胜率；每配对 100 局（候选固定侧 A，先后手由种子自然均摊——沿用 D-030-4 口径）
- **配对集划分**：池内 36 无向配对 → 训练 24 对 + holdout 12 对；分层抽样（保证 9 个 archetype 两侧都覆盖），抽样种子钉死在调优定义 YAML（可复算）
- **公共随机数降方差**：所有候选在同一配对上使用同一固定种子区间（pair i → 种子 200000+i×1000 起 100 局）——确定性同时为 CRN 降方差手段
- **搜索期局数** 100 局/对（CI 半宽 ~±4.4pts，够排序用）；**终选 top-3 复评** 500 局/对（训练+holdout 全量）
- **噪声纪律**：fitness 带噪是已知事实，坐标下降接受新点的规则 = 提升超过噪声门槛（默认 1.0pts，定义文件可调）；同参数重评同分（种子钉死）保证搜索过程本身确定

## 4. 搜索算法（D-T3）

两阶段，先简后繁：

1. **坐标下降粗扫**（主算法）：从默认参数出发，逐维试网格点，优于噪声门槛即采纳并继续；全部维度扫完为一轮，最多 3 轮或整轮无改进停止。副产品 = 逐维敏感性曲线（Δfitness vs 参数值），直接进报告
2. **(1+λ)-ES 精修**（视粗扫结果立项，YAGNI）：以粗扫终点为均值，高斯扰动 λ=16/代，精英均值更新，预算 20 代；仅当坐标下降显示明显维间交互（某维最优点随他维改动而漂移）才启动

预算估算（坐标下降）：10 维 × ~5 点 × ≤3 轮 ≈ 150 次评估 × 2400 局（24 对×100）≈ 36 万局；按 M6 实测吞吐（18,000 局 / 6m15s @16 workers）≈ 2 小时。holdout 验证 + 复校准合计 <10 分钟。

## 5. 工程落点（D-T4）

- **新子包 `battlefrontier/tune/`**：
  - `space.py`——参数空间声明（维度名 / 类别 / 网格点），纯数据
  - `fitness.py`——评估协议（配对划分、种子派生、批量跑局、胜率聚合），复用 runner worker 多进程设施
  - `search.py`——坐标下降主循环（ES 若立项同文件追加）
  - `trajectory.py`——搜索轨迹 JSONL：每次评估一行（参数向量 / 种子区间 / 得分 / 各配对明细），复算锚点
- **CLI**：`bfsim tune <调优定义.yml> [--workers N]`；TuneDef（Pydantic 强校验，不猜纪律同 ExperimentDef）：训练/holdout 划分种子、局数、算法、轮数上限、噪声门槛
- **结果落库口径**：搜索过程局**不落结果库**（36 万局落库无消费场景，轨迹 JSONL 即锚点）；终选参数的全 matrix 复校准走标准 runner 落独立库文件（项目惯例）
- **AgentCfg 零改动**：params 白名单注入已支持任意 HeuristicParams 子集（experiment.py:81）
- **确定性**：搜索器扰动抽样走注入 RandomSource（ tune 定义 seed 字段）；fitness 种子区间确定性派生；同定义同种子重跑轨迹逐行一致

## 6. 验收标准

1. **确定性**：同调优定义同种子重跑，轨迹 JSONL 逐行一致（参数 + 得分 + 种子区间）
2. **holdout 硬门槛**：最优参数在 holdout 12 对（500 局/对）上胜率提升 > 0——不过门槛则本次搜索结论为「默认参数即局部最优」，如实落账不强行回写
3. **复校准**：最优参数全 matrix 36 对 × 500 局落库，与 M6 基线对比（加权 |Δ| / CI 覆盖率变化如实记录，不设死阈值——PRD §10.2 口径延续）
4. **全量 pytest 绿 + ruff 零告警**；坐标下降每步行为单测覆盖（采纳/拒绝/停止规则）
5. **默认参数回写与否 = 用户裁决**（默认参数是 M6–M10 全部基线的锚点）

## 8. 风险与开放项

- **过拟合卡池**：参数在 9 套池上调优，泛化到池外卡组无保证——卡池 v2 落地后需复跑（设计层面接受，写进报告 meta）
- **fitness 对「默认参数对手」的依赖**：调优目标是「打败默认启发式」，可能与「打败人类 meta」有偏——复校准（验收 3）即校正手段
- 开放项：holdout 提升门槛是否应同时要求训练集提升（防「holdout 碰巧为正」）——task 046 跑批前拍板
