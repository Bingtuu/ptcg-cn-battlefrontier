- 摸底依据：2026-10-16 主会话 explore 复勘（evaluate 生产零调用 / mcts.py `_rollout` 截断点 / mcts_consider 结构限制 / 事件流不可离线重建局面）

## 1. 目标与边界

学得局面评估器 V(VisibleGameState) → [0,1]（行动方胜率估计），接入 MCTS rollout 浅截断，
以更低搜索预算保住 2×50 基准的决策质量（D3-2 双锚的 M11 细化见 D-M11-7）。
同时作为学习管线（数据→训练→接入→验收）的端到端最小验证。

非目标：不碰启发式决策规则本体；不调 MCTS 超参（D-035-5）；不做策略蒸馏（M12 域）；
卡池 v1 锚定（D3-5）。

## 2. 设计决策（D-M11-x）

### D-M11-1 数据产线：跑局时显式采集（事件流重建不可行）

- 事实：`play_game` 只回 GameResult 无状态快照；事件流为增量 delta，不含 setup 手牌构成
  与对手侧揭示信息——离线重建决策点局面现状做不到（explore 复勘结论 6）。
- **方案**：`play_game` 驱动循环挂可选 collector 钩子（默认 None = 行为零变化，
  events_hash 回归纪律）；每个 main 阶段决策点记录
  `(visible_state(行动方) 特征向量, action 结构, turn)`，局末回传结局标签
  （行动方胜 1 / 平 0.5 / 负 0）。
- **落盘**：JSONL 侧文件（不落结果库——对齐 tune 轨迹 D-T4 先例）；按配对分文件
  `results/m11-data/<配对>.jsonl`。
- **种子协议**：seed_start=300000，36 配对连续区间（matrix 惯例；与 tune CRN
  区间 200000+ 不重叠）；规模 = 36 对 × 2800 局 ≈ 10.08 万局（≈35min @16 workers，
  task 047 测算口径）。
- **样本量估算**：每局 main 阶段决策点 ~15–20 个 → 150–200 万样本，对线性族充足。

### D-M11-2 特征清单 v1（全部 VisibleGameState 纯函数，信息纪律）

- **A 组（五因子原值）**：prize_diff / board_score / hand_diff / energy_ready_diff /
  deck_diff——以 evaluate 的分解量原值入特征（不是权重乘积）；`evaluate` 生产零调用
  （heuristic.py:91-105 唯一消费方是测试），拆解重构无回归面。
- **B 组（结构量）**：turn（归一化）/ 双方 bench 占用 / 双方 deck_count /
  opponent hand_count / 竞技场在场 0-1 / 双方 active 特殊状态计数 / 双方进化阶段分布 /
  face_down_pokemon 数 / 回合规则标记（能量已附着、支援者已用等 8 个布尔）。
- **C 组（dsl_estimate 衍生，WP1 内增量，先 A+B 跑通）**：己方 active 对对方 active
  有效伤害（`_attack_table` 提取纯函数版，弱点×2/抗性-30）/ 斩杀可达性 0-1 /
  手牌弹药型标记（`has_hand_ammo_pattern`）。
- 纪律：对手隐藏信息只有 count 特征（视图天然如此）；特征名注册进模型资产
  （训练/推理同一份清单，键序钉死）。

### D-M11-3 训练算法：岭回归闭式解（numpy，确定性最优解）

- 选型理由：闭式解 = 位级确定（无 SGD 种子/迭代噪声），numpy 可实现（D3-3 不引学习
  框架），线性族对 150 万样本足够；logistic/SGD 族留作对照不进 v1。
- 标签：行动方结局（1/0.5/0）；**按局 80/20 划分**（同局样本不跨训练/验证集，
  防泄漏）；λ 候选 {0.1, 1, 10, 100} 按验证集 MSE 选定。
- 推理：特征标准化（均值/方差存模型资产）→ 点积 → clamp [0,1]。
- 模型资产：单 JSON（权重 + 特征清单 + 标准化统计 + meta：数据种子区间/代码版本/
  卡池版本/λ）——进版本控制（D3-4）。

### D-M11-4 MCTS 接入：浅截断 + 视角映射

- 插入点：`agent/mcts.py` `_rollout`（237-239 行 cap 判定点）——`turn >= root_turn + K`
  时返回估值；`rollout_turn_cap=50` 的 0.5 兜底保留（K 超过 cap 时行为不变）。
- 视角口径：V 恒从**截断时刻行动方**视角求值（与训练样本同分布），再按 root_player
  映射（root = 行动方 → V；否则 → 1−V）。训练/推理同为 visible_state 视图，
  determinized 世界内隐藏信息已重采样，无泄漏面。
- 注入：`MCTSAgent` 增 params `eval_cutoff_turns`（默认 0 = 禁用，行为零变化）+
  evaluator 资产路径（experiment.py 透传模式对齐 card_effects）；K 扫描
  {5, 10, 15, 20}（D-M11-6）。
- **口径补注（task 052 实施确认）**：turn = 引擎轮计数 `state.turn`（core.py:2309，
  仅先手方回合开始时 +1，即双方各行动一轮为一 turn）——K 的实际截断深度 ≈ 2K 个
  单方回合；训练特征 `turn_norm` 同一计数源，训练/推理分布一致，无线性失真。
  K 扫描网格 {5,10,15,20} 不变（措辞澄清，非口径变更）。

### D-M11-5 决策一致率测量：决策点快照 + 双配置重放（不用字符串标签）

- 事实：mcts_consider 事件载荷的 considered 行动已转可读字符串（play.py `_action_label`），
  choose 类多卡名拼接有碰撞风险；且事件流不含局面。→ 字符串比对判否。
- **方案**：一致率 harness——基准配置（2×50 纯搜索）跑局时 collector 在决策点落
  **序列化 GameState + 教师结构化 Action**（GameState 有序列化往返测试先例）；
  离线载入快照，同状态跑受测配置（降预算 + 评估器），结构化 Action 直接比对 argmax。
- **分母口径 v1**：main 阶段 attack / play_trainer / end_turn 三类决策点；
  剔除唯一合法行动早退点（mcts.py:127-130 不产生考虑）；choose/promote/setup 类
  决策不进 v1 分母（记入附录观察）。
- 快照落 `results/m11-eval/` JSONL（不落结果库）。

### D-M11-6 扫描口径

- K（截断深度）∈ {5, 10, 15, 20} × 预算档 ∈ {2×25, 1×50, 1×25}，定点格先行
  （赛富豪×苍响 + 沙奈朵×赛富豪两格），按一致率-成本曲线选档。

### D-M11-7 双锚的 M11 细化（对三期 PRD D3-2 的显式细化）

- M11 验收锚 = **教师保真**：①决策一致率 ≥ 0.85（D-M11-5 口径，阈值为 v1 目标值，
  实施期若系统性不达可回报修订）；②定点格胜率 CI 覆盖：两定点格（种子区间对齐
  M8c 口径）降预算+评估器配置的胜率 95% CI 覆盖 2×50 基准实测值。
- **meta 锚（复校准加权 |Δ| ≤ 9.7%）归 M12**：M11 的产物是「更省的 MCTS」而非新
  Agent，全 matrix MCTS 口径 68.7h 不适合作为 M11 例行验收；M12 学生达启发式成本后
  meta 锚才可例行执行。此为对 D3-2 的里程碑级细化，已在三期 PRD 框架内。

## 5. 风险与开放项

- **死维度前车之鉴**（task 046）：若 A+B 组特征对结局无可解释方差（验证集 MSE 不优于
  常数基线），如实落账并评估 C 组增量或 M11 降级——不强行过验收。
- **分布漂移**：训练分布 = 启发式自对局局面；MCTS rollout 局面分布有偏移（对手也是
  启发式 rollout，同族）——风险低但需在 M11 报告中用验证集 MSE 与一致率联动佐证。
- **choose 类决策排除**在一致率 v1 分母外：若教师-学生分歧集中在 choose 类，v1 口径会
  系统性高估一致率——附录观察项记录。
- 开放项：一致率阈值 0.85 为 v1 目标值（实施期证据可修订）；C 组特征进 WP1 或顺延。
