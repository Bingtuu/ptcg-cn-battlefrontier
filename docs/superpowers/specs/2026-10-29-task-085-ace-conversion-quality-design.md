## 2. 代码现状（main `a3f1937`，以符号为准）

行号会漂。读 `battlefrontier/agent/heuristic.py`。

### 2.1 主阶段顺序

`_decide_main` 的顺序是：

特性 → 进化 → 附能量 → **`_lethal_attack`** → 附道具 → 撤退 → 物品 → 支援者 → 竞技场 → 使用竞技场 → **`_pick_attack`** → `end_turn`。

能量、进化、特性在斩杀短路**之前**。道具、撤退、物品、支援者、竞技场在短路**之后**。攻击会结束回合，所以短路命中时，本决策不会再打那些训练家。

`_lethal_attack` 只问 `_ko_prize_lookahead`：`can_ko` 且 `attack_index` 对上合法攻击就返回。开关开时，一层 `via=="copy"` 的击杀也算。084 Q2=C 维持这一点。

因此「短路跳过训练家」只发生在**这一步已经能斩杀**的决策上。复制路径还没付清、或者付清了但 `can_ko` 仍为假时，物品和支援者仍排在 `_pick_attack` 前面。能量从来不被这条短路跳过。

### 2.2 前瞻看见复制，非斩杀排序看不见

`_ko_prize_lookahead` / `_lookahead_on_active`：已付清招式里，一层 `copy_attack`（只 `selector=own_bench_attack`）用 `_one_layer_copy` 的伤害；否则用 `_attack_table`。有击杀只在击杀里取最大，否则比伤害。`via` 为 `"print"` / `"copy"` / `"none"`。

`_one_layer_copy` 要求复制招式**现在**就付清印面费用。供体不必付费。未知 filter 不猜。不递归。

`_pick_attack`（走不到斩杀时）仍只读 `_attack_table`。印面 `damage=None` 的复制招式在表里是 0。同一只身上只要还有更高的印面伤害，非斩杀排序会选印面那一招。

N的索罗亚克ex 的卡面只有「暗夜王牌」一条、且 `damage` 为空（`cards/N的索罗亚克ex.yml`）。这种**只有一条复制招式**的身体上，`_pick_attack` 没有第二招可挑，改它的排序键不会改变这只宝可梦的出招。这是机制事实。本刀若改 `_pick_attack`，是为了同一规则覆盖「复制 + 印面芯片」的身体，不是因为这一格的索罗亚克ex 会在两招之间选错。

### 2.3 能量打分把复制当成 0

`_newly_enabled_damage` 只给「再贴这一张就从付不起变成付得起」的印面招式打分。估算为 None 时用 `atk.damage or 0`。复制招式没有印面伤害，启用它的分数是 0。费用仍是印面 `_energy_satisfied` / `_cost_satisfied`，不读 `modify_attack_cost`。

`_one_layer_copy` 不能直接拿来给「还差这一张」打分：它在未付清时返回 None。要打分，得在**假设多了一张能量**之后再走同一层复制。这是实现细节，写在计划里，不新增第二套复制遍历。

079 已经把一部分能量从高费第二招挪开，暗夜王牌触及上升。STATUS 仍把能量附着 Top 排除在这一格的主杠杆之外。所以能量打分可以进范围，但预期不是「再提高触及率」。

### 2.4 撤退和换上：能斩杀已经优先，不能斩杀时回到印面分

`_pick_retreat`：战斗场 `can_ko` 则不撤；备战有人换上后 `can_ko` 则换上最高 `best_damage`。谁都不能斩杀，回到 `_pick_retreat_powerless`（付不起才撤）。落后也不撤到更高的非击杀。这条有测试 `test_neither_ko_does_not_retreat_just_because_behind`。

`_pick_promote`：083 Q15，换上后 `can_ko` 优先于 `pokemon_score`，不看落后。不能斩杀的候选之间仍是 `(-pokemon_score, bench_index)`。

`pokemon_score` 的伤害项是 `max(a.damage or 0)`。纯复制、印面伤害为空的身体，这一项是 0，只剩 HP 和撤退。公式本身冻结。本刀若要让「复制输出」参与排序，用前瞻的 `best_damage` 做**另外的键**，不改这个函数，也不改 `tests/test_features.py` 的期望。

`_copy_donor_key` / `_copy_attack_key`（080）已是「能斩杀优先，再比伤害」。对手战斗场是谁，决定这一下拿几张奖（引擎 `PRIZE_BY_RULE_BOX`：无规则盒 1，ex/V/VSTAR 2，VMAX 3）。供体选择不改变**同一个**防守者的奖赏张数，除非复制出来的招式本身带 `prize_bonus`。本刀不改 080 的 chooser。

### 3.1 建议的 B（零卡名）

只认下面四项，都从 `_ko_prize_lookahead` / `_one_layer_copy` 读，不新写复制语义：

1. **能量。** 某一招满足现有的「再贴一张就付清」（`_energy_role == "enable"`，印面费用）。若在「多这一张」的假设下 `_one_layer_copy` 返回伤害，`_newly_enabled_damage` 用这个伤害，不用 `atk.damage or 0`。已经付清的招式不在这函数里。不读减费。
2. **撤退。** 战斗场和备战都没有 `can_ko` 时：备战某只 `via=="copy"` 且 `best_damage` **严格大于** 战斗场前瞻伤害，才撤到这些候选里伤害最高、下标最小的一只。印面更高、但 `via!="copy"` 的备战，仍不因「伤更高」而撤（081 的反例保持）。战斗场自己 `can_ko` 时仍不撤。
3. **换上。** 能斩杀的候选仍按 083：击杀优先，击杀之间仍比 `pokemon_score`。没有任何 `via=="copy"` 且 `best_damage>0` 的候选时，排序与今天相同。有这样的候选时，**不能斩杀的那一层**改按前瞻 `best_damage`，再比 `pokemon_score`。副作用要写进拍板：这一层里的印面身体也会按前瞻伤害排，而不再先比 HP 分。原因是复制伤害和 `pokemon_score` 不是同一个量纲，硬把「任意复制永远排前」会让 30 点复制压过 200 点印面。
4. **非斩杀 `_pick_attack`。** 前瞻 `via=="copy"` 时，那一个 `attack_index` 用 `best_damage`，其它招式仍用表。单招复制身体上这是无操作。多招时，复制伤害高于印面芯片才改选复制。斩杀仍在更早的短路里处理，这里不第二次短路。

`ko_prize_lookahead_gate=False` 时复制对前瞻不可见，上面四条都看不到 `via=="copy"`，行为回到今天。两个开关正交：总闸关，转换闸无事可做。

## 4. 决策草案

### D-085-1 转换指什么

**转换** = 一条一层复制路径已经付清，或再贴一张印面能量就付清，并且前瞻能给出伤害之后，能量、撤退、换上、非斩杀出招让这条输出被打出来。

度量是局级：B 的 prizes 胜、以及（若数得出来）打出该复制招式的那些局的 B 胜率。不是「再把触及率从 57–72% 往上抬」。
