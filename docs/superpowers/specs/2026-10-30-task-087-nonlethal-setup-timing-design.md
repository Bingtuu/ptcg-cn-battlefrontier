## 1. 背景与证据

### 1.1 问题形态

`_decide_main` 顺序：… → `_lethal_attack` → 道具 → 撤退 → **物品** → **支援者** → … → `_pick_attack`。

当复制/王牌**已付清**但 `can_ko` 为假时，085 会让 `_pick_attack` 打出复制伤害（芯片/磨血）。同时物品/支援者仍在攻击之前——但排序是 `min(iid)`，**没有**「这一张 setup 是否比挥砍更值」的比较。真人常见：付清暗夜王牌后，若打不死，先球/篮子/能量线/支援者，再挥砍。

085 解决「看得见复制输出」。本刀解决「**非斩杀时**是否先做能提高下击杀概率的 setup」。

### 1.2 硬约束：不得破坏 084 Q2=C

| 情形 | 必须行为 |
|---|---|
| 前瞻 `can_ko` | **立刻** `_lethal_attack`；不因手牌有训练家而推迟 |
| 现有回归 | `test_copy_ko_attacks_before_supporter` 必须保持绿 |

任何「有 setup 就推迟攻击」**只允许**在 `can_ko == False`。

## 2. 代码现状（事实）

- `_lethal_attack`：只看 `_ko_prize_lookahead.can_ko`
- 物品/支援者：合法列表上 `min(iid)`（deck-low 抽牌抑制）
- `_pick_attack`：无斩杀时取伤害最高（085 下复制可读前瞻伤害）
- 能量附着已在斩杀**之前**；本刀主要影响「斩杀之后、非斩杀攻击之前」的训练家 vs 最终攻击时序，以及是否在本回合选择 `play_trainer` 而非落到 `_pick_attack`
- 今天：有物品时总会先打物品（若列表非空），再支援者，最后才攻击。问题更细：**(a)** 无价值的物品仍挡住更好的攻击节奏；**(b)** 更关键的是——当 Agent 已经走到攻击时，没有「回跳」去打高价值 setup；但因顺序固定，只要物品列表非空就会先物品。真实缺口是：**用窄 `_setup_value` 决定哪些训练家值得在非斩杀前打出，哪些应跳过以便本回合挥砍，以及（对称）当攻击即将发生时是否应优先仍合法的高价值 setup。**

更准确的产品叙述（与实现挂钩）：

> 当 `can_ko` 为假、复制/王牌路径已付清时：若手牌存在 `_setup_value` **严格大于** 本回合挥砍价值（芯片伤害效用）的训练家（物品/支援者，及可选能量已在更前），则打该 setup；若所有训练家 `_setup_value` ≤ 挥砍，则跳过它们（或按现序但允许「跳过零价值」）进入 `_pick_attack`。`can_ko` 为真时整条不生效。

「跳过物品」今天只能靠：该 subtype 列表被滤空，或开关让 `_decide_main` 在非斩杀时比较后再决定是否 `return` 训练家。计划里写清比较点，不在此锁死函数名。

## 3. `_setup_value` 窄定义（D-087-1）

**只认三类正分（零卡名，读 DSL / 可见状态）：**

| 类 | 条件（概念） | 分值口径（实现留给计划，须可单测） |
|---|---|---|
| **E · 启用下一能量** | 打出后能使某只在场宝可梦对已可见复制/印面招式从付不起变为付得起，或再贴一张后前瞻 `can_ko` | 高：直接使下击杀可见；中：仅启用非斩杀输出 |
| **S · 检索使下回合可 KO** | 训练家含 search/draw（在非 deck-low 抑制下），且检索/抽牌目标类型能使备战或手牌出现付清后 `can_ko` 的路径（保守：能启用已知复制供体或已知高伤身体进场） | 保守估计；未知 filter 不猜 |
| **H · 治疗使扛住对方斩杀** | 治疗/减伤后，己方战斗场有效 HP 从「对方已付清招可 KO」变为「不可 KO」 | 只在对方前瞻可估时 |

**明确不算 setup（分 = 0 或负）：**

- 纯抽牌在 deck-low 抑制下
- 与击杀/存活/启用无关的 stadium 品味（本刀不改 stadium 序）
- 卡名特判加分

**挥砍价值（chip）：** 当前 `_pick_attack` 将打出的有效伤害（085 下含复制前瞻），相对对手剩余 HP 的进度；未过斩杀线时用伤害本身（或伤害/剩余）作比较键。拍板后计划钉死一种，避免双键漂。

**严格大于：** setup 分 > chip 分才 defer 挥砍 / 才优先该训练家。相等则维持今天顺序（不折腾）。
