## 2. 代码现状（main `38db931`，以符号为准）

### 2.1 主阶段顺序

`_decide_main`：特性 → 进化 → 附能量 → **`_lethal_attack`** → 附道具 → 撤退 → 物品 `min(iid)` → 支援者 `min(iid)` → 竞技场 → **`_pick_attack`** → `end_turn`。

### 2.2 拿奖与送奖今天各看哪里

己方能击杀对手战斗场时，`_lethal_attack` 与 `_pick_retreat` / `_pick_promote` 的 `can_ko` 分支已经会打、会换。这刀不推迟它。

没有击杀时，`_pick_attack` 仍挥伤害最高的一招。没有「这一挥会不会在下回合被换走两张奖」的判断。

`_pick_promote`（`ko_prize_lookahead_gate` 开着时）的顺序：

1. 任一候选 `via=="copy"` 且 `best_damage>0`：`copy_conversion_gate` 的 `conv_key`（能击杀优先，否则更高复制伤害）。
2. 否则若落后且同样有可见复制：`prize_race_gate` 的 `race_key`。这是 086，同种子持平。
3. 否则 `ko_key`：能击杀优先，不能击杀则 **`pokemon_score` 最高**，平手下标小。

`pokemon_score` = HP + 印面最高伤害 + 撤退费惩罚。它不看对手打不打得死，也不看规则盒奖张。第一下王牌之前，复制伤害通常还是 0，086 的分支进不去，换上落在第 3 步。高分身体可以是一张规则盒 ex（昏厥送 2 张）即使对手战斗场上已经附着的能量打得死它。

### 2.3 对手打得死，看得见的部分

`VisibleOpponentState.active` 是完整的场上宝可梦（能量、伤害、招式印面都在）。对手手牌张数可见，内容不可见。

启发式里没有对称的「对手这一招对己方打多少」。`_attack_table` / `_ko_prize_lookahead` / `_copied_strike` 都是**己方打对手战斗场**。`estimate_attack_damage` 存在，但是喂的是己方视图。

因此「少送奖」若要存在，要新写一个只读可见战斗场的伤害估计。读不懂的招式不猜，这只候选就不算「打得死」。看不见的手牌（下回合附能、换位、物品）不计入。漏计会让 Q3 变小，这是可接受的方向：门失败就收口，不把猜出来的威胁写进启发式。

奖张表在引擎 `PRIZE_BY_RULE_BOX`（`ex` / `V` / `VSTAR` = 2，`VMAX` = 3，其余 1），`core._knockout_one` 使用。启发式今天不读这张表。`extra_prize_tera_ko` / `extra_prize_attack_ko` 在 `PlayerState` 上，**不在** `VisibleSelfState` / `VisibleOpponentState` 里。默认机制只用规则盒基线，不加看不见的加成。

### 2.4 没有「本局是否已经挥过王牌」的记忆

`VisibleGameState` 没有「己方本局已使用复制招式」的位。Agent 的 `observe` 也不该为这一刀开始记历史。

可观察的代理：换上候选里是否已经有人 `_ko_prize_lookahead.via=="copy"` 且 `best_damage>0`。有，则今天走 085/086 的键，089 不插入。没有，才落到 `pokemon_score`，089 才有空位。这比「事件流里第一下暗夜之前」略窄：能量已经付清、伤害已经 >0、但还没挥的那一拍，089 不开。窄是故意的，避免和 086 抢同一拍。
