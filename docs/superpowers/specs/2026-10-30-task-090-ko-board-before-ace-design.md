### 2.1 主阶段顺序

`_decide_main`：特性 → 进化 → 附能量 → **`_lethal_attack`** → 附道具 → 撤退 → 物品 `min(iid)` → 支援者 `min(iid)` → 竞技场 → **`_pick_attack`** → `end_turn`。

`can_ko` 为真时攻击先于训练家（084 Q2=C）。本刀默认不把任何支援者挪到 `_lethal_attack` 前面。

### 2.2 复制伤害今天长什么样

`_ko_prize_lookahead` 在招式费用已付清、且文档是一层 `copy_attack` / `own_bench_attack` 时，把供体招式并进前瞻。供体自己的费用不要求付清。`_one_layer_copy(..., extra_types=)` 的额外属性只参与**战斗场这张王牌的费用**，不写进供体的伤害。

`_copied_strike` 对供体招式做估算；估算为 None 时用印面伤害。弱点 ×2、抗性 −30，属性用**战斗场**的 `energy_type`。

`can_ko` 为真时 `_lethal_attack` 已经会打。本刀不推迟它，也不另写一套斩杀。

### 2.3 支援者今天不看「换上来能不能被复制打死」

物品和支援者都是 `min(iid)`。没有「这张训练家的效果是 `switch` + `opponent_bench`」的分支。`_pick_choose` 在这种池上仍按 `pokemon_score`（088 的 C 没有进 main）。

088 的计数脚本只在**已经打出的** `choose` 上找 switch。手里有牌、但排序选了另一张支援者的局，不会出现在那 9/40 里。

### 2.4 证据卡上，付能不抬复制伤害（叙述，不进启发式）

库内带伤害、且能被 `owner_pokemon:N` 复制的招式：

| 招式 | 伤害从哪来 |
|---|---|
| 力量愤怒 | 自己身上的伤害指示物 ×20 |
| 复燃 | 对手弃牌区基本能量张数 ×30 |
| 纯真火焰 | 印面 170 |
| 焚身加农炮 | 印面 90，另对备战 90 |

## 6. 代码与证据上还没钉死的点

1. 40 个种子不在仓库里。重算对不上 40 就停。088 脚本对「首触未转化」的操作型定义在 `experiments/t088_q3_frequency.py`；090 的重放沿用那句，不另发明转化。
2. 「结算伤害 0」是 088 脚本在攻击链上对 `opponent_active` 的 `damage` 事件取的。它不等于决策当时的 `best_damage`。Q3 用前瞻。两者若分叉，两列都写回，先停，不写测试。
3. 弱点是否让某印面伤害已经 ≥ 证据卡的剩余 HP，由 `_copied_strike` 在重放里回答。规格不写死属性，也不写「170 一定打得死」。
4. S 依赖今天的 `pokemon_score` 赢家。这个函数在冻结清单里，本刀不改它的权重。
5. 换位之后奖张、伤害指示物、特殊状态会不会让下一次 `_lethal_attack` 的 `can_ko` 和「剩余 HP ≤ best_damage」不一致。实现前的计数用同一出口 `_ko_prize_lookahead` 在**换位之后的视图**上再看一次；对不上就不要把那一局算进 15。本 PR 不写这段代码。
6. `extra_prize_*` 仍不在可见状态里。多个 KO 目标时本刀不排序，因为目标排序不改。
