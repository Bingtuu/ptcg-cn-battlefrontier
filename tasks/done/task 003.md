# task 003 · 阶段机与合法行动枚举

- 状态：完成（2026-08-25）
- 关联：PRD §6.2（阶段机）、§6.4（规则正确性策略）、§7.1（Agent 接口）；里程碑 M1

## 目标

实现回合阶段状态机与"枚举合法行动 → Agent 选择 → 引擎推进"的核心循环。白板范围：不执行任何卡面效果，只跑规则骨架。

## 验收标准（测试清单）

阶段机（每条标注官方规则书/Q&A 出处）：

- [x] 开局：掷币定先后手 → 双方抽 7 → 放置基础宝可梦（战斗场 1 + 备战区任意）→ 设置 6 张奖赏卡 → 先攻方首回合不可攻击（简中现行规则，需标注出处）
- [x] 回合流转：抽牌阶段 → 准备阶段 → 战斗阶段 → 回合结束检查，顺序不可逆
- [x] 准备阶段自由序：进化（每回合每只限一次、登场首回合不可进化）、能量附着（每回合限 1 张）、撤退（白板期暂不收费或按卡面 stub）
- [x] 战斗阶段：白板招式固定伤害；伤害指示物结算；昏厥判定 → 奖赏卡拿取 → 对换上场
- [x] 胜负判定：拿完奖赏卡 / 对手无场上宝可梦 / 对手无牌可抽，三种胜利条件均有测试
- [x] 平局路径可表达（双方同时无宝可梦等），计 0.5 的口径与 db 项目 matchup 矩阵一致

行动枚举与 Agent 接口：

- [x] 每个局面 `legal_actions(state, player)` 返回完整合法行动列表，Agent 选择非法行动时引擎拒绝并抛错
- [x] `Agent` 协议定型：`observe(visible_state, legal_actions) -> action`（PRD §7.1）
- [x] 无可用行动时引擎自动推进（如战斗阶段无能量可攻 → 强制结束回合）

## 实现要点

- 引擎对卡牌内容零硬编码：白板期卡定义走 stub（宝可梦只有 HP + 一个固定伤害招式，训练家卡不可用）
- 每步推进发出结构化事件（为 §5.4 事件流预留，本 task 只保证事件可记录、字段可扩展）

## 结果与遗留

- **结果**：45 测试全绿 + ruff 零告警。新增模块：`engine/actions.py`（Action + IllegalActionError）、`engine/events.py`（GameEvent 结构化事件流）、`engine/core.py`（GameEngine：开局/mulligan/阶段机/合法行动枚举/主阶段四行动/攻击/昏厥/奖赏/换上/三种胜负）、`agent/base.py`（Agent 协议 runtime_checkable）。规则出处在 core.py 逐条注释（规则书·游戏准备/回合的进行/进化/能量/撤退/昏厥/胜负）。
- **TDD 记录**：四循环——A 开局（RED 6 测）→ B 回合流转 + C/D 主阶段与战斗（RED 13 测）→ Agent 协议（RED 2 测）；期间修复均为测试期望笔误（stub- 前缀、布阵后手牌数），引擎行为与规则一致。
- **遗留**：①特殊状态回合间结算（中毒/灼伤伤害、睡眠/麻痹掷币）白板期无触发源，随 M2 效果落地补；②mulligan 对手抽牌与掷币让先选择权当前自动化，Agent 化留待决策层；③白板期撤退按 stub 卡面 retreat_cost 收费。
