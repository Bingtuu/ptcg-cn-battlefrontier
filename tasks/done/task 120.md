# task 120 · 盘面快照回放

- 状态：待立项细化（引擎事件面改动，先侦察再 TDD）
- 关联：task 074（精简对局日志 B / render_log）/ task 108（事件序）；使用便利性 P1
- 日期：2026-11-14 立项（四层优化拍板 P1）

## 目标

回放从「只有操作行」升级为「操作行 + 每回合末盘面快照」：战斗场/备战/附着能量/奖赏/手牌数一屏可读——备赛学习材料的核心形态。

## 设计要点（侦察后定案）

- 引擎在回合末发射 `board_snapshot` 结构化事件（权威状态，不从事件流反推——不猜纪律）；事件入流确定性不受影响（同种子 events_hash 仍逐局一致，串并一致）。
- `render_log` 渲染快照为紧凑文本表；旧库（无快照事件）回放维持现状（兼容）。
- 先侦察：事件发射点、render_log 结构、存量测试对事件序列的断言面（task 108 教训：事件面改动必须 replay 抽查）。

## 验收标准

1. 快照事件内容单测（字段完整、双方盘面正确）。
2. 回放渲染含快照表；旧库回放不破。
3. replay 抽查（同种子并行 vs 串行 events_hash）不变式成立；全量 pytest 绿 + ruff 零告警。

## 结果与遗留

- **实现 ✅**：`_on_turn_end` 收尾发射 `board_snapshot`（双方战斗场/备战/手牌/牌库/奖赏；`_effective_hp` 同口径剩余 HP + 附着能量数）；`_on_turn_end` 被回合结束路径 + 检查入口补调重复经过 → 末位事件去重（同回合同玩家只发一条）。`render_log` 特判渲染为两行盘面表（旧库无此事件 = 现状不破）。
- **测试（验收 1–2 ✅）**：`tests/test_board_snapshot.py` 2 测（事件字段完整 + 渲染表）；红→绿。
- **全量（验收 3 ✅）**：事件面只增不改，1693 + determinize 29 全绿（零存量断言改动）；task 108 事件序纪律保持（快照为新增 kind，不进 `_DEFERRED_EVENT_KINDS` 缓冲集——昏厥结算序不受影响）。
- **遗留**：回放抽查（并行 vs 串行 events_hash）随全量回归的 determinism 套件覆盖；提交随 119/121 同批。
