## 背景与动机

2026-11-14 太晶伊布备赛研究（`experiments/t1114-*`）验证了一个模式：**单卡替换敏感性可以产出可行动的备赛结论**（败因解剖 → 选刀位 → CRN 成对验证）。Owner 拍板：换卡搜索将成为项目关键能力。当前基础设施只有「人工指定刀位的单次敏感性」（task 113/115/117），缺三样东西：

1. **搜索空间定义**：该搜哪些槽位、候选从哪来（当前凭败因直觉拍脑袋）；
2. **验证标准**：多少局、什么显著性门槛、多重比较怎么处理（当前每次临时决定）；
3. **效率路径**：全组合暴力不可行时的筛选→确认两阶段设计。

本任务交付一份方法论设计文档（+ 最小可跑的搜索原型），作为后续「卡组优化器」正式立项的依据。

## 研究问题

1. 搜索空间：给定卡池 v2 一张 60 卡表，合法替换的候选集合如何生成？（同名多印刷 in_id 纪律 task 115、DSL 覆盖过滤、赛制合法性、能量/进化线结构约束）
2. 目标函数与验证：以「vs 指定对手 field 的期望胜率」为目标时，模拟局数、CI 门槛、实际显著性（practical significance）阈值、族错误率控制分别怎么定？
3. 预算分配：筛选阶段（低局数扫全空间）→ 确认阶段（CRN 成对高局数）的两阶段设计，局数与假阳性/假阴性率如何量化？
4. 与现有架构的接口：复用 `bfsim sensitivity`（variants/swaps）、`check-deck` 预检、`field_pick` 期望胜率合成的边界在哪？哪些要新增 CLI？

## 验收标准

1. 设计文档落 `docs/digs/2026-11-14-deck-swap-search-design.md`，覆盖上述四问，每问给出**定案或显式 trade-off 表**（不定案的问题列出候选方案 + 推荐 + 待 Owner 拍板项）；
2. 候选生成器规则成文：槽位分类（能量/进化线/训练家/打手单卡位）、候选来源（池内高使用率单卡 top-N、败因触发的针对性件、用户手填）、过滤链（DSL 覆盖 → 赛制 → 60 张结构合法）；
3. 预注册判据草案：筛选/确认两阶段的局数档位、净胜 CI 门槛、多重比较校正方法（写明理由，参照 task 117 的 2,000 局口径与 task 110 PAIR_MIN_N 纪律）；
4. 原型：`bfsim swap-search --deck <deck_id> --vs <deck_id> --budget <n>` 最小实现（单卡替换扫描 + 两阶段验证 + 排序输出），带限定语头注；或论证原型不立项的理由；
5. 用太晶伊布卡表（mik_moe:711874）做一次端到端演示，与 t1114 人工刀位结果交叉验证（搜索器是否自己找到「加火伊布ex / 加保护」这类刀位）；
6. sim 限定语纪律不破：一切输出内嵌「自对局先验」限定语。

## 结果与遗留

### 交付物

- 方法论设计文档 `docs/digs/2026-11-14-deck-swap-search-design.md`：四问（搜索空间 / 验证标准 / 两阶段预算 / 架构接口）各给定案或 trade-off 表 + 预注册判据 §6（先于演示跑批冻结）+ 8 项待 Owner 拍板项 §7。
- 原型 `battlefrontier/report/swap_search.py`：槽位分类（五类机械口径）、候选源（同 archetype 邻近卡组高频 top-N + `--include` 手填败因件）、过滤链（同印刷 → DSL 覆盖三态 → `db.validate_deck` → 同名多印刷换出槽拒绝，拒绝逐类 reason 计数）、两阶段预算分配（60/40 + 下限/超预算报错，不静默截断）、确认档 Bonferroni α/k + BH 双校正判定（CI 不过 0 且 |ΔWR|≥3pp 且 p_bonf<0.05 = 候选刀位）、限定语头注 + 筛选档「不宣称显著」禁令。
- CLI：`bfsim swap-search --deck <id> --vs <id> --budget <n>`（`cli.py` `_cmd_swap_search`，子命令懒加载接入）。

### 收尾复验修复（4 处小 bug，均未改设计）

1. `benjamini_hochberg` 排序 bug：`sorted((i, p) …)` 元组排序按索引而非 p 值，含 None 且乱序输入时 rank 错——修 `key=lambda t: t[1]`（测试参考值原本正确）。
2. `dsl_reject_reason` 三态顺序 bug：vanilla 态（同名有文档、本印刷未挂）须先于纯白板豁免判拒，原实现让「纯白板的 vanilla 异文本印刷」混过豁免——对齐 `coverage.py side_coverage` 归类顺序（vanilla 优先于 pure_vanilla）。
3. 测试笔误：`include=("友好宝芬 [CSV7C-178]")` 缺尾逗号（str 逐字符迭代），补逗号。
4. 测试脆弱点：`_real_candidates` 原 top_n=2——真实 db 下 top-2 高频件（猫头夜鹰/巢穴球）在阵均已 4 张，加第 5 张被 4-of 关合法全拒、过滤链全灭，改 top_n=6。
