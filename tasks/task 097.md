- 状态：no-go 已收口（未合并 main）
- 关联：M14；`docs/superpowers/specs/2026-10-31-phase4-accuracy-validity-design.md` §4.1

## 目标

用最多 600 局 2×50 MCTS 和同种子启发式 CRN，判断至少两个独立高残差配对是否存在可复现的策略深度改善信号，并给出 M15 单候选 go/no-go。未达成就回滚分支并重新规划，不将 MCTS 参照冒充部署候选。

## 验收标准（测试清单）

- [x] development 的 10 对完整进入问题清单；full/validation 不参与选格。
- [x] 逐种子配对改善量与 95% CI 有先红后绿测试，覆盖同向、反向、零方差、种子不一致、平局和失败局（`tests/test_paired.py`，11 passed）。
- [x] 四个首批试点各 100 局 2×50 MCTS，与 300000..303099 既有启发式逐种子对齐，失败 0。
- [x] 仅点估计改善的高残差对进入第二批；至多两对，追加 MCTS 与同种子启发式各 100 局，失败 0。
- [x] 至少两个独立高残差对连续两批 CI 下界 >0，且对照无显著恶化才 go；否则 no-go、停止且不合并。
- [x] 报告含逐格残差、CRN CI、成本、归因和 go/no-go；不夸大 MCTS 参照含义。
- [x] 全量 pytest 与 Ruff 通过，STATUS 与 task 同步；no-go 不合并 main。

## 实现要点

1. 新增纯报告统计：按共同种子读取双方 A 侧胜负，`d=mcts_a_win-heuristic_a_win`，方向 `s=sign(real_wr-heuristic_wr)`，对 `s*d` 的均值计算样本标准差正态近似 95% CI。任一侧平局/失败或种子集不一致显式报错。
2. 首批 MCTS 配置与既有启发式使用完全相同的 deck_id、seed_start、games=100；agents 两侧均为 2×50 MCTS，不使用评估器截断。
3. 第二批按文档顺序分配 304000/305000 段，并补跑同种子启发式，保证配对检验不偷换对照。
4. 报告保存到 `docs/digs/`，实验定义进版本控制，结果库留本机 `results/`。

第二批按门槛仅选择点估计为正且无显著反向的多龙×N索（304000..304099）与多龙×电电虫（305000..305099）；同种子启发式与 MCTS 各 100 局，均失败 0。
