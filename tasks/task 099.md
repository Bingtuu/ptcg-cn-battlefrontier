## 调研结论（机制定位，本 task 第一步已完成）

task 098 的候选描述为「早期 use_ability 选择性门槛」，机制调研后发现更精确的价值落点：

1. **MCTS 在主线决策点看不到牌库顶**（`determinize.py:126` 己方 deck 顺序每次 determinize 都重洗；冻结集只应用于挂起根）→ MCTS 的「用/不用」触发决策是真实的 ex-ante 评估，不依赖窥视。
2. **挂起根冻结**（`determinize.py:9-13`，D-039-2）→ 一旦触发，选择步的候选池对搜索方全已知。事件流证实：MCTS 使用点的后续 `mcts_consider`/`choose` 事件完整披露牌库顶 2 张与最终取舍。
3. **68 个早期使用点中，MCTS 在选择步「不拿（pass）」33 次（48.5%）**——拿的情况也常是能量/奇树等边际卡（z1+z2 实计）。即 MCTS 的主要选择性发生在**选择步（拿/不拿、拿哪张）**，而该步信息（顶 2 张内容 + 牌库余量）在真实对局中对任何 Agent 完全可见。
4. 启发式现状（`heuristic.py:477-489` + actions 段取最高评分）：选择步**几乎总是拿最高分卡、从不主动 pass**（pass 得分为 0，而 pokemon_score / 能量 / 训练家评分通常为正——仅低 HP 高撤退费宝可梦理论上可为负），且按 pokemon_score 贪心拿牌、把另一张埋入牌库底。

结论：**gate 的主攻点 = 选择步的拿/不拿决策（G1，完全可观测）**，而非主线触发抑制（G2）。G2 只作预注册回退，不在本 task 实现。

## 预注册规则（G1，≤3 条，效果结构检测、无卡名硬编码）

检测条件：挂起选择步，其来源效果为 `search_deck`（selector=own_deck、args.top_n 小、args.rest=deck_bottom、min_choose=0 的检索统一 up-to 纪律）。命中的选择步按以下规则评估（v(x) = 启发式既有 keep 评分：能量 1.0 / 训练家 0.5 / 宝可梦 pokemon_score）：

- **R1（双废 pass）**：max(v1, v2) < V_JUNK → pass。
- **R2（关键件保护）**：v(被埋卡) ≥ V_KEY 且己方 deck_count ≥ DEEP → pass（早期厚牌库埋关键件代价高）。
- **R3（薄牌库白拿）**：deck_count ≤ SHALLOW → 总是拿 v 最高者（覆盖 R1；后期埋牌代价≈0）。

参数标定（三阶段分离，防参数选择过拟合）：
- **拟合（z1）**：只用 `results/m14-drag-zoro-mcts.db` 的多龙奇选择步（419 使用点；早期 turn≤3 为 34 点、其中 pass 15 次）。
- **内嵌验证（z2）**：阈值在 `results/m14-drag-zoro-confirm-mcts.db`（396 使用点；早期 34、pass 18）上过线才保留——判据：与 MCTS 拿/不拿决策一致率 ≥70%，且该规则命中 ≥20 个选择点（不足即废弃该规则，宁可少规则不可少样本）。
- **确认（800000 段新种子）**：最终验证 OOS。
- 网格预注册（粗粒度，无连续自由度）：V_JUNK ∈ {0.5, 1.0, 1.5, 2.0}；V_KEY ∈ {2.0, 3.0, 4.0, 5.0}；DEEP ∈ {20, 25, 30}；SHALLOW ∈ {10, 15, 20}。目标函数 = z1 上 take/pass 决策一致率最大；脚本落 `.kimi-code/t099_calibrate_gate.py` 并入本分支。

## 结果与遗留

**结论：G1 选择在标定阶段被预注册协议否决（2026-11-02），gate 未实现，零 Agent/DSL/引擎行为变更。**

证据链（复现：`.kimi-code/t099_calibrate_gate.py`，结果 `results/t099-calibration.json`）：

1. **标定 FAIL**：z1 网格最优一致率 51.7%，z2 只有 48.7%——低于「总是拿最优」基线（z2 pass 率 48.9% → 基线 51.1%）。即 3 条规则在这些可观测特征上**没有任何可泛化的分离信号**。R1 命中 0、R2 命中 7–9（门槛 20），仅 R3 命中但等价于基线。
2. **MCTS 选择步本身是噪声主导**：pass 率在全部回合桶几乎恒定（z1：44.1%/44.1%/51.5%，z2：52.9%/48.8%/52.1%），与 deck_count 无结构关系；选择步 margin 中位 = 2 访问（总 100），多龙奇**触发点** margin 中位 = 1，且 34% 的触发点 chosen action 甚至不是访问数领先者。
3. **机制重判**：task 098 的 +21.7pts 条件效应建立在 2×50 预算下近乎掷币的逐决策输出上，更可能是「条件相关 + 搜索噪声」的混合，而非可由 ≤3 条可观测规则复制的因果结构。task 098 记录中「MCTS 只在大约三成局面使用」的解读需修正：**这三成里的大部分不是选择性，是搜索预算不足下的随机触发**。
4. 调研期另一结论仍然成立且已核实：主线根 deck 重洗（`determinize.py:126`）、挂起根冻结披露顶 2 张（D-039-2）、事件流在使用点披露顶 2 张与取舍——G1「完全可观测」的前提没错，错的是「MCTS 在这些点有可学习的确定性偏好」这一假设。

**遗留与下一步候选**（不在本 task 范围，需另行决策）：

- task 098 的 +21.7pts 候选模式整体降权：低预算 MCTS 单点决策 near-tie 率过高，决策差异挖掘应优先使用 margin 过滤（如 chosen_visits − max(other) ≥ 10）筛掉噪声点后再评估模式，此为 task 098 工具的改进项而非新验证。
- 若仍要追该配对，剩余方向是 G2（主线触发抑制）——但其证据同样来自这批 near-tie 决策，预期价值低，不建议在未加 margin 过滤重估前立项。
- 校验成本：标定只读解析既有库，零 MCTS、零新对局（约 5 秒墙钟）。
